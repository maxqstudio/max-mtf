# REPAIR v0.8.3 — Champion-stop, auto-refinement, and Windows atomic I/O

v0.8.3 is a bounded repair of the v0.8.2 Strategy Optimizer lifecycle. It does not change EA strategy logic, Research gates, Optimizer KPI, ranking, or the Owner manual training-data workflow.

## Closed defects

- `START` and `RESUME` process the latest compatible existing MT5 XML first. `RESUME` never reruns the checkpointed MT5 round.
- An eligible winner is the terminal optimization authority: bypass Scientist, apply only whitelisted optimized defaults to canonical `EA_v1_06`, compile/deploy it, then stop for Owner manual MT5 backtest. No later optimization round is legal.
- A parsed no-winner round automatically continues when `round < frozen max_rounds`: refine the bounded search space, compile the same canonical EA, then launch exactly the next native MT5 round.
- Scientist range authority exists only on that automatic no-winner refinement: OFF=`DETERMINISTIC_ONLY`; successful real LLM proposal=`SCIENTIST_PROPOSAL`; unavailable/failed provider/model/call=`DETERMINISTIC_FALLBACK`. Proposal, deterministic acceptance/rejection, provenance and failure reason are persisted.
- If the last allowed round still has no winner, state is `NO_CHAMPION_MAX_ROUNDS` and Optimizer stops.
- Optimizer form state is durable across navigation, sidebar changes, Streamlit reruns and app restart. Active jobs consume only their frozen request; live edits affect the next run.
- The old separate recovery action and manual Continue action are absent. Contextual actions are only `START AUTO OPTIMIZER`, `RESUME AUTO OPTIMIZER`, or `STOP OPTIMIZER`.
- `historical external: status.json`/evidence/config/EA atomic writes use unique same-directory temp files with fsync and bounded Windows PermissionError/WinError 5/32 retry. The launcher stores PID ownership in `historical external: worker_process.json` and does not rewrite worker-authoritative `historical external: status.json` after spawn.
- MT5 SpreadsheetML `<Created>` is provenance only, never round-freshness authority. Every newly launched round snapshots all compatible reports before MT5 starts, prefers the unique requested round filename, and otherwise accepts only a new/changed compatible file fingerprint. This prevents a stale compatible XML from being reused as a later round when MT5 timestamps are timezone-shifted or future-dated.
- Every parsed round persists exact report SHA-256, report-selection mode, parsed-pass count, eligible-pass count, KPI thresholds and per-gate counts. `eligible_passes > 0` with no deterministic Champion is a hard invariant failure, never a no-Champion continuation.
- Optimizer UI exposes the exact evidence report name, parsed passes, eligible count and report SHA prefix. Scientist provenance reads the persisted top-level LLM provenance so `SCIENTIST_PROPOSAL` does not render `MODEL —` when a real model was used.

## Evidence contract

Job/round evidence records state transitions, `first_failed_gate`, frozen config, internal report identity, report SHA/fingerprint/selection provenance, KPI eligibility audit, Scientist path/reason, next-range proposal, and terminal/continuation reason. Internal XML identity remains EA + Symbol + Timeframe + From + To. Filename is never sufficient authority by itself; the unique requested filename is only a freshness preference after internal identity matches.


## R4 — Fresh Optimizer evidence + naming authority
- New Optimizer START excludes prior MAX-generated reports from bootstrap evidence, including both legacy `MAX_StrategyOptimizer_*` and current `historical external: Max_R<N>.xml` names.
- Canonical EA runtime name is `Max` (`EA_v1_06/Max.mq5` -> `Max.ex5`).
- Optimizer artifacts share the EA stem: `historical external: Max_R<N>.xml` and `Max_R<N>.set`.
- Legacy filenames remain recognized only for backward-compatible discovery/recovery; they are never generated by new runtime flows.
